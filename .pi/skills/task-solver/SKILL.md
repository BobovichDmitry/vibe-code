# Task Solver

Скилл основного агента для разбора очереди задач в `tasks/`. Запускается одной фразой пользователя (например, «реши одну задачу») и за один проход решает задачу целиком либо запрашивает недостающую информацию.

## Контракт очереди (tasks/)

Содержимое папки `tasks/` и правила работы с ней описаны в `tasks/agents.md`. Кратко:

- `tasks/index.md` — **источник истины и порядка задач**. Не папка `todo/`, а именно этот файл.
- `tasks/todo/` — файлы невыполненных/ожидающих задач.
- `tasks/done/` — выполненные задачи (файл переносится сюда + внутрь дописывается краткая реализация).

### Канонический формат `tasks/index.md`

```md
# Tasks Index

## Todo
1. [task-slug.md](todo/task-slug.md) — краткое описание
2. [another-task.md](todo/another-task.md) — краткое описание

## NeedInfo
<!-- задачи, ожидающие ответа от пользователя. Вопросы — внутри файла задачи -->

## Done
<!-- выполненные задачи. Файл перенесён в done/, детали — внутри файла -->
```

- Порядок в **Todo** — сверху вниз (нумерованный список). «Первая задача» = верхний пункт Todo.
- **NeedInfo** — задачи с открытыми вопросами пользователю (файл остаётся в `todo/`, переносится только пункт в index).
- **Done** — выполненные задачи со ссылкой на `done/<file>`.

> Дрейф: если в `todo/` лежит файл, которого нет в Todo — не берись за него автоматически, сообщи пользователю. Если Todo ссылается на несуществующий файл — сообщи.

## Алгоритм (выполняется за один проход)

### 0. Загрузи контекст очереди
1. Прочитай `tasks/index.md` и `tasks/agents.md`.
2. Найди верхний пункт раздела `## Todo` — это текущая задача. Файл — по ссылке `todo/<name>`.
3. Если Todo пуст → сообщи «Очередь Todo пуста» и остановись. Если есть пункты в `## NeedInfo` — перечисли их и спроси, не хочет ли пользователь ответить.
4. Прочитай файл задачи `tasks/todo/<name>`.

### 1. Анализ задачи
Пойми суть, найди затронутый код (через `rg`/`read`). Определи, хватает ли информации для уверенной реализации прямо сейчас.

### 2. Выбери ветку (критерии — ниже)
- **SOLVE** — реализуй задачу целиком и оформи результат (шаг 3).
- **NEEDINFO** — запиши вопросы пользователю и переведи в NeedInfo (шаг 4).

Решение принимается **в этом же проходе**. Не должно быть «я подумаю и вернусь» — либо делаешь, либо спрашиваешь.

### 3. Ветка SOLVE — реализуй и оформи

1. **Реализуй** изменение в коде по конвенциям проекта (см. «Ограничения проекта» ниже).
2. **Проверь типы/сборку**: для бэкенда — `cd apps/backend && npx tsc --noEmit`; для фронта — `cd apps/frontend && npx vue-tsc --noEmit` и/или `npm run build:frontend`. Не запускай dev-серверы и не запускай e2e, если пользователь не просил.
3. **Перенеси файл**: `git mv tasks/todo/<name> tasks/done/<name>` (если не в git — `mv`).
4. **Допиши реализацию** в перенесённый файл `tasks/done/<name>` секцию (в конец, после исходного текста задачи):
   ```md

   ---

   ## Реализация (YYYY-MM-DD)

   - Что сделано (файлы/эндпоинты/компоненты).
   - Ключевые решения и trade-off.
   - Как проверено (tsc/vue-tsc/build).
   - Остаточные риски / TODO.
   ```
5. **Обнови `tasks/index.md`**: удали строку задачи из `## Todo` и добавь одной строкой в `## Done` (с датой):
   ```md
   - [<name>](done/<name>) — краткое описание (YYYY-MM-DD)
   ```
   Перенумеруй Todo.
6. **Документация**: если изменение нетривиальное — после оформления пригласи `@docs-maintainer обнови docs` (через subagent). Для самой `tasks/` документация не нужна.
7. **Краткий отчёт пользователю**: что сделал, какие файлы, как проверил.

#### Особый случай: задача уже выполнена
Если при анализе выяснится, что требуемое уже реализовано (например, в коде уже есть нужный механизм) — не переделывай. Оформи как SOLVE с пометкой «уже реализовано в <файл>:<строка>», перенеси в `done/`, в `## Done` добавь пометку `(уже было реализовано)`.

### 4. Ветка NEEDINFO — запроси уточнения

Используй эту ветку, когда есть **существенная неоднозначность** или нехватка внешних данных. Примеры:
- Несколько равнозначных трактовок, меняющих результат (что именно считать/где разместить/какой формат).
- Нужны внешние данные: ключи, доступы, ссылка на референс, прод-значение, макет.
- Задача зависит от другой невыполненной задачи или от решения пользователя.

Действия:
1. **Допиши вопросы в файл задачи** `tasks/todo/<name>` секцию (в конец):
   ```md

   ---

   ## Вопросы (NeedInfo, YYYY-MM-DD)

   1. <конкретный вопрос с контекстом и вариантами>
   2. ...
   ```
   Файл **остаётся** в `todo/` (не переносится).
2. **Обнови `tasks/index.md`**: перенеси строку задачи из `## Todo` в `## NeedInfo` (оставь ссылкой на `todo/<name>`). Перенумеруй Todo.
3. **Коротко сообщи пользователю**: какую задачу взял и какие вопросы появились (с номерами), со ссылкой на файл.

#### Возврат из NeedInfo
Когда пользователь ответил:
1. Допиши ответ в файл задачи (секцией `## Ответ (YYYY-MM-DD)`).
2. Перенеси строку задачи обратно в `## Todo` (наверх) в `tasks/index.md`.
3. Если ответа достаточно — сразу переходи к ветке SOLVE (можно тем же сообщением).

## Ограничения проекта (из корневого AGENTS.md)

- **Не запускай dev-серверы** (`dev:backend:log`, `dev:frontend:log`) и **не запускай e2e** сам — это делает пользователь. Для проверки используй `tsc --noEmit` / `vue-tsc --noEmit` / сборку. Читать логи (`logs/backend.log` и т.д.) можно.
- **Не вызывай `chrome_devtools_*` напрямую.** Весь браузерный труд — через сабагента `browser-checker` (subagent).
- После изменений в коде — поддерживай `docs/` через `docs-maintainer`.
- Пиши на русском (включая описания в `tasks/done/` и отчёт пользователю).
- Соблюдай архитектуру из корневого `AGENTS.md` (API prefix `/api`, TypeORM entities, Vue 3 + Tailwind SPA, hash-router, и т.д.).

## Чек-лист одного прохода

- [ ] Прочитал `tasks/index.md` + `tasks/agents.md`, определил первую задачу Todo.
- [ ] Прочитал файл задачи, провёл анализ кода.
- [ ] Выбрал ветку: SOLVE или NEEDINFO.
- [ ] SOLVE: реализовал → проверил типами/сборкой → `git mv` в `done/` → дописал «## Реализация» → обновил index (Todo→Done) → (опц.) docs-maintainer → отчёт.
- [ ] NEEDINFO: дописал «## Вопросы» в файл → обновил index (Todo→NeedInfo) → краткий отчёт с вопросами.
