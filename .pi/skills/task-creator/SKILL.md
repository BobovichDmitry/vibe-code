# Task Creator

Скилл основного агента для **интерактивного создания новой задачи** в очереди `tasks/`. В отличие от `task-list-converter` (пакетная конвертация готового файла-списка) и `task-solver` (разбор существующей задачи), этот скилл ведёт с пользователем короткий диалог, чтобы превратить разговорную идею в готовую к реализации задачу.

## Главная идея (что делает скилл уникальным)

1. **Задача появляется в очереди СРАЗУ** — при первом же сообщении пользователя создаётся файл `tasks/todo/<slug>.md` и пункт в `tasks/index.md` → `## NeedInfo`. Никакого «я создам потом». Очередь — источник истины; раз задача зазвучала, она уже в ней.
2. **Жёсткий инвариант: пока задача не финализирована — она в `NeedInfo`.** В процессе диалога задача ВСЕГДА лежит в `## NeedInfo` (файл физически в `tasks/todo/`). Это сознательно: отдельная неоконченная задача не должна «отнимать очередь» у готовых задач в `Todo`, и пользователь по `index.md` видит, что по ней ждут его ответа.
3. **Минимум вопросов.** Спрашивать только то, что **реально влияет на реализацию** и чего нельзя вывести из кода. Если после первого сообщения всё понятно — предложить финализацию сразу, без «обязательных» уточнений ради уточнений.
4. **Финализация = явная команда.** Пользователь говорит «финализируй / всё / готово / ок, оформляй» → скилл приводит файл к полному шаблону (Контекст, Acceptance, Подсказки, Проверка) и переносит пункт `NeedInfo → Todo`.

## Когда использовать

Триггеры (скилл подгружается по описанию автоматически):

- «давай создадим задачу» / «создай задачу про ...»
- «заведи задачу в очередь» / «добавь в очередь задачу»
- «оформи как задачу ...» / «сделай задачу из этого»
- «хочу задачу: ...»

Или явный вызов: `/skill:task-creator`.

## Контракт очереди (tasks/)

Правила — в `tasks/agents.md`. Кратко (то, что важно этому скиллу):

- `tasks/index.md` — источник истины и порядка задач.
- `tasks/todo/` — файлы невыполненных и **ожидающих** задач (включая NeedInfo — файл остаётся здесь, в `index.md` пункт уходит в `## NeedInfo`).
- Канонические разделы `index.md`: `## Todo` / `## NeedInfo` / `## Errors` / `## Done`.

```md
# Tasks Index

## Todo
1. [task-slug.md](todo/task-slug.md) — краткое описание

## NeedInfo
<!-- задачи, ожидающие ответа. Вопросы — внутри файла (тут и незавершённые диалоги task-creator'а) -->

## Errors

## Done
```

## Алгоритм

### 0. Активация — создай черновик СРАЗУ

На первое сообщение пользователя (даже если в нём уже есть полное описание):

1. Прочитай `tasks/agents.md` и текущий `tasks/index.md` (чтобы не дублировать и корректно вписать пункт).
2. Сформулируй **slug** (см. «Slug-конвенция» ниже).
3. **Проверь дубликат** по slug/смыслу в существующих разделах `index.md` и в `tasks/todo/`, `tasks/done/`. Если задача уже есть — не создавай новую, сообщи пользователю (предложи дополнить существующий файл). Стоп.
4. **Кратко изучи код** (`rg`/`read`) — ровно настолько, чтобы понять: какие файлы/эндпоинты/компоненты затронуты, что уже есть, чего не хватает. Глубокий анализ — не здесь (он будет при финализации); тут нужен лишь контекст для осмысленных вопросов.
5. **Создай файл** `tasks/todo/<slug>.md` по **шаблону DRAFT** (ниже) — с исходной формулировкой пользователя, контекстом-наброском и списком открытых вопросов.
6. **Обнови `tasks/index.md`**: добавь пункт в `## NeedInfo` (НЕ в `Todo`!), со ссылкой `todo/<slug>.md` и кратким описанием. Перенумеруй `Todo`/`NeedInfo`.
7. Сообщи пользователю: задача создана в `NeedInfo`, задай уточняющие вопросы (см. шаг 1).

### 1. Уточнения — МИНИМУМ вопросов

**Принцип скупости.** Задавай вопрос, только если:
- без ответа **реально непонятно**, что реализовать (что именно считать / где разместить / какой формат / поведение в ключевом edge-case);
- нужно **внешнее данное** (макет, ключ, доступ, ссылка-референс, прод-значение);
- есть **несколько равнозначных трактовок**, дающих разный результат.

**Не спрашивай**, если ответ:
- выводится из кода (`rg`/`read` — сам найди);
- это техническая деталь, которую агент обоснованно выберет сам (паттерн, имя переменной, место в файле);
- «хорошо бы уточнить» без влияния на результат.

**Лимиты:** как правило, **1 раунд** с **1–3 вопросами**. Если после первого сообщения понятно всё — не задавай ни одного, сразу предложи финализацию (шаг 3, команда). Многораундовый допрос — антипаттерн.

Каждый ответ пользователя:
1. Допиши в файл задачи в секцию диалога (шаблон DRAFT, раунды) — что спросил, что ответили.
2. При необходимости переформулируй контекст-набросок.
3. Файл **остаётся** в `tasks/todo/`, пункт **остаётся** в `## NeedInfo` (инвариант). Никаких переходов в `Todo` без финализации.
4. Если ответов достаточно для реализации и новых вопросов нет — предложи финализацию одной фразой: «Похоже, всё есть. Финализирую? (или добавь ещё детали)».

### 2. Реакция на реплику пользователя в ходе диалога

Агент сам классифицирует сообщение:

- **Ответ на вопрос** → шаг 1 (допиши в файл, `NeedInfo`, продолжи).
- **Новые детали/уточнение** → допиши в файл (секция диалога или уточни контекст), `NeedInfo`.
- **Команда финализации** («финализируй», «всё», «готово», «ок, оформляй», «достаточно») → шаг 3.
- **Отмена** («забудь», «отмени», «не надо») → удали файл `tasks/todo/<slug>.md`, убери пункт из `## NeedInfo`, подтверди отмену.
- **Смена темы** (пользователь заговорил о другой задаче) → сначала спроси, финализировать ли текущую или отменить; не бросай черновик в `NeedInfo` без решения.

### 3. Финализация — оформи готовую задачу

По команде пользователя:

1. **Глубже изучи код** (`rg`/`read`), если не сделал этого на шаге 0 — найди конкретные файлы/методы/эндпоинты, существующие паттерны для переиспользования.
2. **Перепиши файл** `tasks/todo/<slug>.md` по **шаблону FINAL** (ниже): исходная формулировка + `## Контекст (анализ кода)` + `## Acceptance criteria` + `## Подсказки по реализации` + `## Проверка`. Диалоговую секцию можно свернуть в короткую заметку «## Уточнения из диалога» или убрать, если ответы уже вошли в Контекст/Acceptance.
3. **При необходимости переименуй файл** (`git mv tasks/todo/<old>.md tasks/todo/<new>.md` если в git, иначе `mv`), если slug оказался неточным после прояснения сути. Сообщи новое имя.
4. **Обнови `tasks/index.md`**: перенеси строку задачи из `## NeedInfo` в `## Todo` (наверх списка, нумерованный). Перенумеруй оба раздела.
5. **Краткий отчёт пользователю**: что за задача (slug), куда легла (`Todo`), 1–2 строки сути + ссылка на файл. Без воды.

## Шаблоны файлов

### Шаблон DRAFT (процесс создания, лежит в NeedInfo)

```md
<исходная формулировка задачи пользователя — как есть, можно слегка причесать>

> ⏳ **Статус: создание задачи (диалог).** Задача ещё не финализирована — собираем уточнения. Лежит в `## NeedInfo`.

---

## Контекст (набросок, уточняется)

- <что предварительно понятно из кода; какие файлы/эндпоинты предположительно затронуты>
- <что переиспользуем, чего предположительно не хватает>

## Уточнения из диалога

### Раунд 1 (YYYY-MM-DD)

**Вопросы:**
1. <конкретный вопрос с контекстом и вариантами>

**Ответы:**
1. <ответ пользователя, когда придёт>
```

> Файл **остаётся** в `tasks/todo/`; пункт в `index.md` — в `## NeedInfo`.

### Шаблон FINAL (после финализации, лежит в Todo)

```md
<исходная формулировка задачи>

---

## Контекст (анализ кода)

- <что нашёл в коде: какие эндпоинты/методы/компоненты уже есть, что переиспользуем, чего не хватает>
- <ссылки на конкретные файлы: `apps/.../X.vue`, `apps/.../Y.ts`>
- <существующие паттерны проекта, которые применимы>

## Acceptance criteria

- <конкретное, проверяемое условие>
- <...>
- <edge-cases: пустой ввод, подчат read-only, гонки и т.п.>

## Подсказки по реализации

- Все правки — <только фронт / фронт+бэк / ...> (файлы: ...).
- <что переиспользовать: метод X уже импортирован, composable Y, паттерн из Z>
- <на что обратить внимание>

## Проверка

- `npx vue-tsc --noEmit` в `apps/frontend` и/или `npx tsc --noEmit` в `apps/backend` — без ошибок. dev-серверы и e2e не запускать (по правилам проекта).
```

> Та же структура, что у задач из `task-list-converter` — консистентно для `task-solver` / `task-batch-solver`.

## Slug-конвенция

- `snake_case`, английский, ~2–4 слова, отражает **действие/суть** (не транслит русского).
- Примеры: `export_reminders`, `add_user_avatar`, `bulk_delete_users`.
- Уникален в рамках `tasks/` (проверяй по `todo/`, `done/`, `index.md`).
- Формируется из **первого** сообщения; при финализации можно переименовать, если прояснилась суть.

## Обновление tasks/index.md

- Создание (DRAFT): пункт → `## NeedInfo`, нумерованный, со ссылкой `todo/<slug>.md` и кратким описанием.
- Финализация (FINAL): та же строка переносится `NeedInfo → Todo` (наверх списка). Перенумеруй оба раздела.
- Описание — **краткое** (одно предложение), техническая суть + в скобках ключевой механизм. Пример:
  > `export_reminders.md` — экспорт напоминаний в JSON (кнопка в RemindersView, новый backend-эндпоинт `GET /api/reminders/export`)
- Не трогай существующие пункты (кроме перенумерации).

## Дедупликация

- Если задача (по slug или смыслу) уже есть в `index.md` (Todo/NeedInfo/Done) или в `tasks/todo/`/`tasks/done/` — **не создавай новый файл**. Сообщи: «Задача „X" уже есть как `<slug>` (в ...)». Предложи дополнить существующий файл, но не перезаписывай.

## Ограничения проекта (из корневого AGENTS.md)

- **НЕ запускай dev-серверы** (`dev:backend:log`, `dev:frontend:log`) и **НЕ запускай e2e**. Скилл обычно не пишет код — только файлы задач; проверка типов нужна, только если что-то поправил попутно (`tsc --noEmit` / `vue-tsc --noEmit`).
- **НЕ вызывай `chrome_devtools_*` напрямую** — браузер через сабагента `browser-checker`.
- Пиши на русском (формулировки, контекст, вопросы, отчёт).
- Соблюдай архитектуру и конвенции `tasks/` из `AGENTS.md` и `tasks/agents.md`.

## Чек-лист одного прогона

**Активация:**
- [ ] Прочитал `tasks/agents.md` + `tasks/index.md`, проверил дубликат.
- [ ] Сформировал slug, кратко изучил код (`rg`/`read`).
- [ ] Создал файл `tasks/todo/<slug>.md` по шаблону DRAFT.
- [ ] Добавил пункт в `## NeedInfo` в `index.md` (НЕ в Todo), перенумеровал.
- [ ] Задал 0–3 содержательных вопроса пользователю (или предложил финализацию, если всё ясно).

**В ходе диалога:**
- [ ] Каждый ответ дописан в файл (раунд диалога); пункт остаётся в `## NeedInfo`.
- [ ] Классифицировал реплику (ответ / детали / финализация / отмена / смена темы).

**Финализация:**
- [ ] Углубил анализ кода.
- [ ] Переписал файл по шаблону FINAL (Контекст, Acceptance, Подсказки, Проверка).
- [ ] (Опц.) Переименовал файл, если slug неточен.
- [ ] Перенёс пункт `NeedInfo → Todo` в `index.md`, перенумеровал.
- [ ] Краткий отчёт пользователю (slug, суть, ссылка).

## Примеры

### Пример 1 — короткий диалог

```
Пользователь: давай создадим задачу: кнопка экспорта напоминаний в json

Агент: [создаёт tasks/todo/export_reminders.md (DRAFT) + пункт в NeedInfo]
       Нашёл `RemindersView.vue` (шапка списка) и `reminders.controller.ts` — endpoint'а
       экспорта пока нет. Два вопроса:
       1. Формат — только JSON, или ещё CSV?
       2. Экспортировать все напоминания или с выбором диапазона?
       (Файл в NeedInfo: tasks/todo/export_reminders.md)

Пользователь: только json, все

Агент: [дописывает ответы в файл, остаётся в NeedInfo]
       Понял. Финализирую? Больше вопросов нет.

Пользователь: да, оформляй

Агент: [переписывает файл по шаблону FINAL, переносит NeedInfo → Todo]
       ✅ Задача `export_reminders` в Todo: кнопка в RemindersView →
       GET /api/reminders/export (json всех напоминаний). Файл: tasks/todo/export_reminders.md
```

### Пример 2 — сразу финализация (всё понятно)

```
Пользователь: создай задачу: показывать лоадер при загрузке списка пользователей

Агент: [изучает код: ManageUsersView.vue (нет индикатора) + паттерн в RemindersView.vue]
       Всё понятно — паттерн уже есть в RemindersView. Вопросов нет.
       Сразу финализирую? [DRAFT создан в NeedInfo]

Пользователь: давай

Агент: [FINAL → Todo]
       ✅ `users_loading_spinner` в Todo.
```

### Пример 3 — отмена

```
Пользователь: добавь задачу: ...

Агент: [DRAFT в NeedInfo, вопросы]

Пользователь: ладно, забудь, передумал

Агент: [удаляет tasks/todo/<slug>.md, убирает пункт из NeedInfo]
       Ок, отменил — файл и пункт из очереди удалены.
```
