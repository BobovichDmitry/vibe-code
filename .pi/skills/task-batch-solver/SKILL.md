# Task Batch Solver

Оркестратор очереди `tasks/`. В отличие от `task-solver` (одна задача за проход руками основного агента), этот скилл проходит **всю** очередь `## Todo` до конца, **делегируя каждую стадию субагентам с чистым контекстом**, и **коммитит в git после каждой задачи**.

## Роли (плоский fan-out от основного агента)

| Роль | Кто | Контекст | Что делает |
|------|-----|----------|------------|
| Оркестр | **основной агент (ты)** | эта сессия | цикл по задачам, координация, git, `tasks/index.md` |
| Код | `code-solver` | fresh | реализует задачу + проверяет `tsc`/`vue-tsc`/build |
| E2E-тесты | `e2e-writer` | fresh | пишет Playwright-спеку под решённую задачу (браузерно-CDP или API-стиль) |
| E2E-прогон | `test-runner` | fresh | гоняет спеку, отчёт |
| E2E-починка | `test-fixer` | fresh | чинит, если красно |
| Докум. | `docs-maintainer` | fresh | обновляет `docs/` |

Все субагенты запускаются **последовательно** (один писатель на cwd в каждый момент), у всех `disallowed: [subagent]` — вложенности нет. **Ты (оркестратор) не пишешь код** — только координируешь, делаешь git и ведёшь `index.md`.

## Главный цикл

Повторять, пока в `tasks/index.md` есть пункты в `## Todo`:

### Шаг 1. Взять задачу
1. Прочитай `tasks/index.md`. Верхний пункт `## Todo` — текущая задача. Файл — по ссылке `todo/<name>`.
2. Если `## Todo` пуст → **выход из цикла** → «Финальный отчёт».
3. Прочитай файл задачи `tasks/todo/<name>`.
4. Запиши короткий заголовок в ответ пользователю: «▶ Задача N: <name> — <краткое описание>».

### Шаг 2. Реализация → субагент `code-solver`
```text
subagent({
  agent: "code-solver",
  task: "Реализуй задачу из tasks/todo/<name>. Прочитай файл задачи, изучи код по AGENTS.md, реализуй изменение, проверь типы (apps/backend: tsc --noEmit; apps/frontend: vue-tsc --noEmit). Верни сводку по своему формату (SUCCESS/NEEDINFO/FAILED)."
})
```
Разбор `## Результат:`:
- **SUCCESS** → запомни сводку (файлы, как проверено) → Шаг 3.
- **NEEDINFO** → ветка **NEEDINFO** (ниже) → к Шагу 1 (следующая задача).
- **FAILED** → ветка **ERROR** (ниже) → к Шагу 1.

### Шаг 3. E2E-тесты → субагент `e2e-writer`
```text
subagent({
  agent: "e2e-writer",
  task: "Напиши e2e-тест (Playwright, e2e/tests/) для РЕШЁННОЙ задачи tasks/todo/<name>. Сводка реализации от code-solver: <вставь сводку>. Изучи существующие спеки в e2e/tests/, выбери подходящий стиль (браузерно-CDP через connectedPage из e2e/fixtures.ts ИЛИ API-стиль через axios против E2E_API_URL). Если e2e неуместен (чистый визуал без детерминированной проверки, требует реального внешнего провайдера) — верни NOT_APPLICABLE с объяснением. Сами тесты не запускай. Верни ответ по своему формату."
})
```
Разбор `## Результат:`:
- **SUCCESS** → запомни путь к спеке → Шаг 4.
- **NOT_APPLICABLE** → отметь «e2e н/у: <причина>», **пропусти Шаг 4** → Шаг 5.
- **FAILED** → ветка **ERROR** → к Шагу 1.

### Шаг 4. Прогон e2e → субагент `test-runner`
```text
subagent({ agent: "test-runner", task: "Запусти npx playwright test <spec> (из директории e2e) и верни отчёт." })
```
Разбор:
- **ЗЕЛЁНО** (все тесты спеки прошли) → Шаг 5.
- **КРАСНО** → один цикл починки через `test-fixer`:
  ```text
  subagent({ agent: "test-fixer", task: "Почини e2e-тест <spec>. Реализация задачи (code-solver): <сводка>. Если тест некорректен — правь тест; если баг в коде — правь код. Перепроверь и верни итог." })
  ```
  затем снова `test-runner` по той же спеке. Если **снова КРАСНО** → ветка **ERROR** → к Шагу 1.

> Примечание: для e2e-прогона нужен запущенный backend (`npm run dev:backend:log`). Пользователь поднимает backend вручную. `test-runner` запускает только `npx playwright test` — НЕ dev-серверы. Режим браузера управляется env (`E2E_USE_BROWSER`, `E2E_HEADLESS` в `e2e/.env`).

### Шаг 5. Документация → субагент `docs-maintainer`
```text
subagent({ agent: "docs-maintainer", task: "Обнови docs/ после реализации задачи tasks/todo/<name>. Изменения: <сводка от code-solver>. Затронутые области: <угадай по файлам — backend/frontend/database/e2e/admin>." })
```
Если `docs-maintainer` упал — не блокируем: отметь «docs не обновлены» в коммите и иди дальше (код и тесты важнее).

### Шаг 6. Git commit (один на задачу)
```bash
cd D:/work/projects/amorev/vibecode-setup
git add <конкретные пути изменённых файлов>
git commit -m "<type>(<scope>): <краткое описание задачи>

- Реализовано: <1-2 строки от code-solver>
- E2E: <e2e/tests/xxx.spec.ts | н/у: <причина>>
- Docs: обновлены | не тронуты

Задача: tasks/done/<name>"
```
- `type`: `feat` / `fix` / `refactor` / `test` / `docs` / `chore`.
- `scope`: область (`auth`, `users`, `reminders`, `frontend`, `e2e`, `database`, и т.д.).
- Запиши **хеш коммита** (`git rev-parse HEAD`) для отчёта по задаче.

> **ВАЖНО:** НЕ используй `git add -A` / `git add .` — в рабочем дереве могут быть чужие незакоммиченные правки. Перед коммитом проверь `git status`: коммить ТОЛЬКО файлы, относящиеся к текущей задаче, через `git add <конкретные пути>`.

### Шаг 7. Оформить задачу
1. `git mv tasks/todo/<name> tasks/done/<name>`.
2. Допиши в `tasks/done/<name>` секцию (в конец):
   ```md

   ---

   ## Реализация (batch, YYYY-MM-DD)

   - **Что сделано**: <из сводки code-solver>.
   - **Файлы**: <список>.
   - **E2E**: <e2e/tests/xxx.spec.ts — N тестов зелёно | н/у: <причина>>.
   - **Docs**: обновлены (<файлы>) | не тронуты.
   - **Коммит**: `<хеш>`.
   - **Проверка**: tsc/vue-tsc OK, e2e зелёно.
   ```
3. `git add tasks/done/<name> tasks/index.md && git commit --amend --no-edit` (влить оформление в коммит задачи) **ИЛИ** отдельный `docs(tasks): оформить <name>`. На твой выбор; проще — `--amend`.
4. В `tasks/index.md`: удали строку задачи из `## Todo`, добавь одной строкой в `## Done` (перенумеруй Todo):
   ```md
   - [<name>](done/<name>) — <краткое описание> (YYYY-MM-DD)
   ```
5. Краткий прогресс пользователю: «✅ Задача N решена и закоммичена (`<хеш>`). E2E: <зелёно|н/у>. → следующая.»

### → к Шагу 1 (следующая задача)

## Ветки ошибок

### NEEDINFO — вопросы пользователю
Когда `code-solver` (реже другой субагент) вернул `NEEDINFO` (неоднозначность / нехватка внешних данных):
1. Допиши в файл задачи `tasks/todo/<name>` секцию:
   ```md

   ---

   ## Вопросы (NeedInfo, YYYY-MM-DD)

   1. <вопрос из ответа code-solver>
   ```
   **Файл ОСТАЁТСЯ в `todo/`.**
2. Откатай кодовую попытку, если code-solver что-то успел поменять: `git status` → если есть изменения в коде (не в файле задачи), `git checkout -- <пути>` или `git stash`. Оставить можно только правки в файле задачи.
3. В `tasks/index.md` перенеси пункт из `## Todo` в `## NeedInfo` (перенумеруй Todo).
4. `git add tasks/ && git commit -m "chore(tasks): <name> → NeedInfo"`.
5. Сообщи пользователю вопросы коротко → к Шагу 1.

### ERROR — техническая неудача
Когда `code-solver` вернул `FAILED`, или e2e не чинится после `test-fixer`:
1. Допиши в файл задачи `tasks/todo/<name>` секцию:
   ```md

   ---

   ## Ошибка (YYYY-MM-DD)

   - **Стадия**: <code-solver | e2e-writer | test-fixer>.
   - **Что пробовали**: <кратко>.
   - **Почему упало**: <из ответа субагента>.
   - **Ключевая ошибка**: <сообщение>.
   ```
   **Файл ОСТАЁТСЯ в `todo/`.**
2. **НЕ коммить сломанный код.** Сохрани попытку для разбора: `git stash push -u -m "wip: <name> (failed)"` (если есть незакоммиченные правки), запиши имя стэша в файл задачи. Либо оставь в рабочем дереве и явно предупреди пользователя.
3. В `tasks/index.md` перенеси пункт из `## Todo` в новый раздел `## Errors` (если его нет — создай после `## NeedInfo`):
   ```md
   ## Errors

   - [<name>](todo/<name>) — <краткое описание> — упало на <стадия> (YYYY-MM-DD)
   ```
4. `git add tasks/ && git commit -m "chore(tasks): <name> → Errors (<стадия>)"`.
5. Сообщи пользователю коротко → к Шагу 1.

## Финальный отчёт (когда `## Todo` пуст)

```markdown
## Готово — очередь разобрана

**Решено и закоммичено:** N
- `<хеш>` <name> — <описание>
- ...

**В NeedInfo (нужны ответы):** M
- <name> — <суть вопросов>

**В Errors (технически не удалось):** K
- <name> — <что упало>

**Рабочее дерево:** чисто / остались <файлы> (вне очереди).
```

## Дрейф очереди
- Если в `todo/` лежит файл, которого нет в `## Todo` — **не бери его автоматически**: сообщи пользователю и спроси, добавить ли в очередь.
- Если `## Todo` ссылается на несуществующий файл — сообщи, пропусти пункт.

## Ограничения (из AGENTS.md)
- **Ты (оркестратор) не пишешь код и не запускаешь dev-серверы/e2e/браузер.** Весь код — через `code-solver`/`e2e-writer`/`test-fixer`; прогоны — через `test-runner`; доки — через `docs-maintainer`; браузер — через `browser-checker` (если понадобится).
- Один коммит на задачу (код + e2e + docs); оформление задачи можно влить через `--amend`.
- Пиши на русском.
- Соблюдай архитектуру из корневого `AGENTS.md`.

## Чек-лист цикла (на каждую задачу)
- [ ] Взял верхний пункт `## Todo`, прочитал файл.
- [ ] `code-solver` → SUCCESS / NEEDINFO / FAILED.
- [ ] (SUCCESS) `e2e-writer` → SUCCESS / NOT_APPLICABLE / FAILED.
- [ ] (SUCCESS) `test-runner` → зелёно / красно → `test-fixer` → зелёно / ERROR.
- [ ] `docs-maintainer` обновил доки.
- [ ] Git commit (один на задачу, точечный `git add`), хеш записан.
- [ ] `git mv` в `done/`, секция «## Реализация», `index.md` Todo → Done.
- [ ] (NEEDINFO/ERROR) вопросы/ошибка в файл, `index.md` → NeedInfo/Errors, коммит, следующая задача.
