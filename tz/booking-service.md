# ТЗ: Сервис бронирования мероприятий

## 1. Обзор

Добавить в существующий NestJS-бэкенд API для бронирования свободных слотов (`FreeSlot`).  
На входе — дата + время слота + текстовое описание.  
На выходе — сохранённое событие в БД и корректное обновление доступности слотов.

---

## 2. Текущая архитектура

| Сущность | Таблица | Описание |
|----------|---------|----------|
| `EventEntity` | `event` | Существующие мероприятия (title, description, startDate, endDate, location, color) |
| `FreeSlotEntity` | `free_slot` | Свободные окна (date, startTime, endTime) — хранят *диапазоны*, а не получасовые слоты |

**Фронтенд** генерирует получасовые слоты из диапазонов `FreeSlot` (метод `generateHalfHourSlots` в `api/events.ts`).

---

## 3. Что требуется

### 3.1. Новая сущность — `Booking`

Создать сущность, связывающую забронированный получасовой слот с описанием:

```
Таблица: booking
├── id                : integer PK
├── date              : date       (например, "2026-05-26")
├── timeSlot          : varchar    (например, "10:00") — старт получасового слота
├── description       : text       (текстовое описание мероприятия)
├── createdBy         : varchar    (опционально, имя/никнейм)
├── createdAt         : datetime
└── updatedAt         : datetime
```

### 3.2. API-эндпоинты

#### POST `/api/events/book`
Забронировать получасовой слот.

**Request:**
```json
{
  "date": "2026-05-26",
  "timeSlot": "10:00",
  "description": "Встреча с клиентом",
  "createdBy": "Иван Иванов"
}
```

**Валидация:**
- `date` — обязательный, формат `YYYY-MM-DD`.
- `timeSlot` — обязательный, формат `HH:MM` (00:00–23:30, шаг 30 мин).
- `description` — обязательный, 1–500 символов.
- `createdBy` — опциональный, 1–100 символов.

**Логика:**
1. Проверить, что слот попадает в какой-либо `FreeSlot` (диапазон). Если нет — вернуть `400 Bad Request`.
2. Проверить, что слот ещё не забронирован (`date` + `timeSlot` уникальны). Если занят — вернуть `409 Conflict`.
3. Сохранить `Booking` в БД.
4. Вернуть созданный объект.

**Response `201`:**
```json
{
  "id": 1,
  "date": "2026-05-26",
  "timeSlot": "10:00",
  "description": "Встреча с клиентом",
  "createdBy": "Иван Иванов",
  "createdAt": "2026-05-25T16:00:00.000Z",
  "updatedAt": "2026-05-25T16:00:00.000Z"
}
```

#### GET `/api/events/bookings`
Все бронирования (упорядочены по `date ASC`, `timeSlot ASC`).

#### GET `/api/events/bookings/date?date=2026-05-26`
Бронирования на конкретную дату.

#### GET `/api/events/bookings/range?start=2026-05-26&end=2026-05-31`
Бронирования в диапазоне дат.

#### PATCH `/api/events/bookings/:id`
Обновить описание бронирования.

**Request:**
```json
{
  "description": "Встреча перенесена, новое описание",
  "createdBy": "Пётр"
}
```

#### DELETE `/api/events/bookings/:id`
Отменить бронирование.

### 3.3. Обновление доступности слотов

При запросе свободных слотов (`/free-slots/date`, `/free-slots/range`, `/free-slots`) **не возвращать** слоты, которые уже забронированы.

**Реализация (на выбор):**

**Вариант А (рекомендуемый):** Добавить в `EventsService` метод `getAvailableSlotsForDate(date)`, который:
1. Находит `FreeSlot`-диапазоны для даты.
2. Находит `Booking`-и для даты.
3. Генерирует получасовые слоты из диапазонов.
4. Исключает забронированные слоты.
5. Возвращает результат.

**Вариант Б (альтернативный):** Не менять бэкенд, а вычитать занятые слоты во фронтенде (на основе `/bookings/date`). Но это сложнее для консистентности.

---

### 3.4. Обновление существующих эндпоинтов Free Slots

Эндпоинты `/free-slots/date` и `/free-slots/range` должны возвращать **доступные** слоты (без забронированных). Либо создать отдельный эндпоинт `/api/events/available-slots/date`, который делает то же самое, но уже с учётом `Booking`.

Рекомендуемый подход — изменить текущие эндпоинты, чтобы они учитывали бронирования.

## 6. Правила валидации

| Правило | Описание |
|---------|----------|
| `date` + `timeSlot` уникальны | Нельзя забронировать один и тот же слот дважды |
| Слот должен попадать в `FreeSlot` | Нельзя забронировать время вне свободных окон |
| `description` обязательный | Минимум 1 символ, максимум 500 |
| `timeSlot` шаг 30 мин | Допустимые значения: `00:00`, `00:30`, `01:00` ... `23:30` |

## 7. Приоритеты

| Приоритет | Задача |
|-----------|--------|
| P0 | CRUD бронирований (`POST/GET/PATCH/DELETE /bookings`) |

| P2 | `GET /bookings/date` и `/bookings/range` |
| P3 | Удаление `HARDCODED_FREE_SLOTS` после миграции на БД |

---

## 8. Примечания

- Бэкенд использует SQLite по умолчанию, PostgreSQL в продакшене — учитывать при миграциях.
- TypeORM `synchronize: true` — схема обновляется автоматически.
- Фронтенд уже генерирует получасовые слоты — не дублировать эту логику на бэкенде.
- Хардкод `HARDCODED_FREE_SLOTS` убрать после того, как `FreeSlot`-ы начнут храниться в БД стабильно.
